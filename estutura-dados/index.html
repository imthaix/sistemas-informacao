Pilhas (Stack)

LIFO — Last In, First Out

Uma pilha é uma estrutura linear com acesso restrito a uma única extremidade: o topo. O último elemento que entra é o primeiro a sair — pense numa pilha de pratos.

Operações essenciais

Operação O que faz
push(item) Insere um item no topo
pop() Remove e retorna o item do topo
peek() Consulta o topo sem remover
isEmpty() Retorna True/False se está vazia
size() Retorna a quantidade de itens
Regra fundamental: acessar sempre pelo topo. Nunca se mexe na base diretamente.

Exemplo visual: push(10) → push(20) → push(30) → pop()

Pilha sequencial

  • Armazenamento contíguo (vetor/lista)
  • Tamanho fixo (pode "estourar")
  • Acesso direto por índice

Pilha encadeada

  • Nós alocados dinamicamente
  • Tamanho cresce/diminui livremente
  • Cada nó aponta para o anterior

Código em Python (lista nativa)

pilha = [1, 1, 2, 3, 5]
pilha.append(8)      # push → insere no FIM
pilha.append(13)
# [1, 1, 2, 3, 5, 8, 13]
pilha.pop()           # pop → remove do FIM
# [1, 1, 2, 3, 5, 8]
Repare: em Python, append() insere no final da lista e pop() remove do final — por isso o final da lista representa o "topo" da pilha.

Aplicações reais (pegadinha de prova!)

Situação Por que é LIFO
Pilha de pratos/bandejas O último colocado é o primeiro retirado
Botão "Voltar" do navegador A página atual fica no topo; volta na ordem inversa
Desfazer (Ctrl+Z) A ação mais recente é desfeita primeiro
Pilha de chamadas de função A última função chamada retorna primeiro

Filas (Queue)

FIFO — First In, First Out

Na fila, a inserção ocorre sempre no fim (rear) e a remoção sempre no início (front). É exatamente como uma fila de banco.

Ordem de remoção: A → B → C → D

Operações fundamentais

Operação O que faz
enqueue(x) Insere x no final
dequeue() Remove e retorna o item do início
isEmpty() Testa se está vazia
size() Retorna a quantidade

Código em Python

class Fila:
    def __init__(self):
        self.itens = []

    def enqueue(self, item):
        self.itens.append(item)      # insere no FINAL

    def dequeue(self):
        if self.isEmpty():
            return None
        return self.itens.pop(0)     # remove do INÍCIO

    def isEmpty(self):
        return len(self.itens) == 0
⚠️ Atenção: pop(0) desloca todos os elementos da lista uma posição — é um ponto clássico de pegadinha sobre custo computacional (O(n) nessa implementação simples).

Variações de fila

Tipo Armazenamento Ponto forte Cuidado
Sequencial Vetor/lista Simplicidade Remoção pode deslocar elementos
Prioridade Heap Seleciona por prioridade Não é FIFO global
Circular Vetor fixo Reaproveita espaço livre Capacidade limitada
Encadeada Nós (ponteiros) Crescimento dinâmico Gasto extra de memória
Pegadinha clássica: "A fila encadeada pode se comportar como FIFO ou LIFO?" → FALSO. Fila é SEMPRE FIFO, independente de como é implementada (sequencial, encadeada, circular). O que muda é só a forma de armazenamento na memória.

Listas Encadeadas

Estrutura composta por nodos, cada um guardando um dado e uma referência ao próximo (ou anterior) nodo.

Pegadinha muito comum: um método chamado insere() pode inserir no início (mais comum em exercícios de pilha/lista simples) ou no fim (mais comum em filas). Sempre leia o código da implementação — nunca assuma pelo nome do método!
  • Inserção no início → novoNodo.proximo = head; head = novoNodo
  • Inserção no fim → percorre até o último nodo e liga o proximo dele ao novo nodo

Árvores Binárias

Estrutura hierárquica

Por que usar árvores? Listas, filas e pilhas são sequenciais — quanto mais elementos, mais difícil manuseá-los, e não representam relações hierárquicas entre dados.

Terminologia essencial

Termo Significado
Raiz (Root) Primeiro nodo (nível 0), no topo. Não tem pai.
Nodo (Node) Elemento da árvore, ligado por arestas aos filhos
Folha (Leaf) Nodo sem filhos (fim de um caminho)
Grau Número de filhos que um nodo possui
Altura Distância máxima entre a raiz e o nodo mais profundo

Regra da árvore binária

Cada nodo pode ter no máximo 2 filhos: um à esquerda e outro à direita. Se não houver filho em algum lado, o apontador é None.
Pegadinhas de identificação (ex.: árvore 1-2-3-4-5-6-7):
  • Nodo 1 = raiz ✔
  • Nodo 4 é filho esquerdo de 2 (não direito!)
  • Subárvore esquerda da raiz = nodos {2, 4, 5}
  • Nodo 7 (folha) nunca é a raiz

Árvore Binária de Busca (BST)

Transforma a árvore em um mecanismo de busca rápido, seguindo uma regra inflexível:

  1. Nodos à esquerda são sempre menores que o pai
  2. Nodos à direita são sempre maiores que o pai
  3. Valores repetidos não são permitidos

Busca na BST — eliminação de metade a cada passo

Procurando o valor 4 na árvore abaixo — a cada comparação, metade da árvore é descartada: 

        8
       / \
      3   10
     / \
    1   6
       /
      4

4 < 8  → vai para subárvore esquerda (nodo 3)
4 > 3  → vai para subárvore direita (nodo 6)
4 < 6  → vai para subárvore esquerda → Encontrado!

Árvore AVL (auto-balanceada)

Problema: se inserirmos dados já ordenados (1, 2, 3, 4...), a BST degenera numa linha reta (como uma lista encadeada) — perde a hierarquia e a busca vira O(n), lenta como busca sequencial.

Solução — Árvore AVL: mantém o fator de balanceamento de cada nodo entre -1, 0 ou +1: 

Fator = Nível da Esquerda (NE) − Nível da Direita (ND)

Quando o fator sai desse intervalo, a árvore faz rotações (para a direita ou para a esquerda) para se reequilibrar.

Caminhamentos em Árvore

Usando a árvore de exemplo:

        A
       / \
      B   C
     /   / \
    D   E   F
       / \   \
      G   H   I

🔵 Pré-ordem (NLR)

Raiz → Esquerda → Direita

Visita o nodo antes de ir para os filhos.

A, B, D, C, E, G, H, F, I

🟢 Em-ordem (LNR)

Esquerda → Raiz → Direita

Primeiro desce todo à esquerda, depois visita o nodo atual, depois vai à direita.

D, B, A, G, E, H, C, F, I

Em uma BST, o percurso em-ordem sempre retorna os valores em ordem crescente!

🟠 Pós-ordem (LRN)

Esquerda → Direita → Raiz

A raiz só é visitada depois de todos os seus filhos.

D, G, H, E, I, F, C, B, A

🟣 Por nível (BFS)

Largura — nível por nível, esquerda → direita

A, B, C, D, E, F, G, H, I

Algoritmo recursivo — em-ordem

def em_ordem(no):
    if no is not None:
        em_ordem(no.esquerda)   # 1º: esquerda
        visita(no)               # 2º: nodo atual
        em_ordem(no.direita)     # 3º: direita
Pegadinha clássica de prova: "A visita inicia no nodo da esquerda" → tecnicamente FALSO. O algoritmo é chamado a partir da raiz (é o ponto de entrada da recursão); só depois ele desce recursivamente até o nodo mais à esquerda antes de fazer a primeira visita efetiva.

Métodos de Busca

Localizar elementos

Fatores que influenciam o algoritmo de busca: tamanho da lista, organização dos dados (ordenados ou não) e estrutura utilizada (vetor, lista encadeada, hash...).

🔎 Busca Sequencial

Percorre a lista elemento por elemento, comparando cada item com a chave procurada, até encontrar ou acabar a lista. 

int busca_sequencial(int v[], int n, int chave) {
    for (int i = 0; i < n; i++) {
        if (v[i] == chave)
            return i;      // posição encontrada
    }
    return -1;             // não encontrado
}
✅ Prós ❌ Contras
Fácil de implementar · não precisa ordenação · funciona em qualquer estrutura Ineficiente para grandes volumes de dados
Exemplo de contagem (muito cobrado!): array [11, 10, 2, 19, 18, 0, 8, 14, 20, 7], buscando 18.
Índices 0,1,2,3 → não bate (11,10,2,19). Índice 4 → bate (18).
São necessárias 5 comparações (1ª até 5ª posição, índice 0 a 4).

🔎 Busca Binária

Dividir para conquistar: a cada iteração, metade dos elementos é descartada. Exige que a lista esteja ordenada! 

int busca_binaria(int v[], int n, int chave) {
    int ini = 0, fim = n - 1;
    while (ini <= fim) {
        int meio = (ini + fim) / 2;
        if (v[meio] == chave) return meio;
        else if (chave < v[meio]) fim = meio - 1;
        else ini = meio + 1;
    }
    return -1;
}

Exemplo: lista [3, 7, 9, 12, 18, 25], buscando 18 → meio=(0+5)/2=2 (elemento 9 < 18) → meio=(3+5)/2=4 (elemento 18, encontrado!)

✅ Prós ❌ Contras
Muito eficiente para grandes volumes Exige dados ordenados · pouco eficiente com inserções/remoções frequentes

🔎 Busca em Tabela Hash

Estrutura que associa chaves a valores usando uma função hash para calcular diretamente o índice de armazenamento. 

Dado (chave) → Função Hash → Índice na tabela
Colisão: quando duas chaves diferentes geram o mesmo índice. Uma solução comum é o encadeamento separado — cada posição da tabela guarda uma lista de pares (chave, valor). 
def inserir(tabelaHash, id, valor):
    idHash = hash(id) % len(tabelaHash)
    lista = tabelaHash[idHash]
    for i, (c, v) in enumerate(lista):
        if id == c:
            lista[i] = (id, valor)   # ATUALIZA se já existe
            return
    lista.append((id, valor))        # senão, insere novo
Pegadinha: se o id já existe na tabela, o elemento é atualizado (substituído), e não duplicado nem excluído com del.
✅ Prós ❌ Contras
Busca, inserção e remoção muito rápidas (idealmente O(1)) Depende de uma "boa" função hash; colisões podem degradar a performance

Métodos de Ordenação

Organizar dados

🫧 Bubble Sort (Ordenação por Bolha)

Compara elementos adjacentes e os troca se estiverem fora de ordem. O maior "borbulha" até o final a cada passagem. 

for i in range(len(array)):
    for j in range(0, len(array) - i - 1):
        if array[j] > array[j + 1]:
            array[j], array[j+1] = array[j+1], array[j]

Identificação: comparação de pares vizinhos + troca (swap) → é Bubble Sort.

📥 Insertion Sort (Ordenação por Inserção)

Divide a lista em parte ordenada e parte não ordenada. Pega o próximo elemento não ordenado e o insere na posição correta dentro da parte já ordenada.

Exemplo decrescente: [8,15,1,-5,-9,2] → [15, 8, 2, 1, -5, -9]. Custo computacional: O(n²) no pior/médio caso.

🎯 Selection Sort (Ordenação por Seleção)

Busca o menor (ou maior) elemento da lista não ordenada e faz apenas uma troca por iteração.

⚡ Quick Sort

Escolhe um elemento pivô e particiona o array: menores à esquerda, maiores à direita do pivô. Repete recursivamente.

🔀 Merge Sort

"Dividir para conquistar": quebra a sequência em subsequências menores, ordena cada uma e depois combina (merge) tudo no final.

Tabela comparativa — Identifique pelo padrão!

Algoritmo Ideia-chave Complexidade típica
Bubble Sort Compara pares adjacentes e troca O(n²)
Insertion Sort Insere na posição certa em relação ao já ordenado O(n²) médio, O(n) melhor caso
Selection Sort Busca o mínimo/máximo, 1 troca por rodada O(n²)
Quick Sort Pivô + partição esquerda/direita O(n log n) médio
Merge Sort Divide, ordena partes, combina (merge) O(n log n)

Tabela Hash — Resumo rápido

Acesso quase O(1)

Já detalhada na seção de busca acima. Pontos-chave para memorizar:

  • Função hash transforma a chave em um índice.
  • Colisão = duas chaves caem no mesmo índice → resolvida geralmente com listas encadeadas (chaining).
  • Inserir uma chave já existente atualiza o valor, não duplica.
  • Performance depende diretamente da qualidade da função hash.
